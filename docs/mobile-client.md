# モバイルクライアント方針

## 結論

初期クライアントはレスポンシブWeb/PWAを推奨する。音声入力を後回しにする場合、Tailnetへ接続したスマートフォンのブラウザから利用でき、アプリストア配布やネイティブのバックグラウンド制約を先に抱えずに済むためである。

## クライアントが知る範囲

クライアントは次のHTTP APIだけを利用する。

- 会話の作成と取得
- メッセージ送信
- 会話履歴取得
- 後続PRで追加するSSEによる実行イベント購読
- 後続PRで追加する承認要求への回答

Kubernetes API、CodexSession CRD、Session Pod、Codex App Server、libSQLには直接アクセスしない。これらはRunner APIの内部実装である。

## 将来のExpo移行条件

次の要件が必要になった場合はExpo/React Nativeを検討する。

- OSのプッシュ通知
- アプリがバックグラウンドにいる間の通知・再接続
- ネイティブ音声入出力
- Secure StorageなどOS機能との統合

その場合も、画面から呼ぶAPI契約はPWAと共通にする。まずAPIをクライアント非依存にすることで、Webからネイティブへ移行してもサーバー側の構成を変えずに済む。
